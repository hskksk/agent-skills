# 調査の2段階モデルとレポート型の自動選択・出力ガイド

調査（リサーチ）は、知識の獲得段階に応じて **「Phase 1: 探索型リサーチ（景観・論点の特定）」** と **「Phase 2: 検証・構造化型リサーチ（答え・根拠の構築）」** の2つの局面に分かれます。

本ガイドでは、ユーザーからの依頼文を分析して適切なレポート型を自動選択する**判定ルール**と、それぞれの**レポート構造ルール**を定義します。

---

## 1. 依頼内容からのレポート型自動判定ルール（ルーティング）

依頼文に含まれる「問いの具体性」「読者の目的」「前提の有無」から、適用すべきレポート型を判定します。

```
[ユーザーからの依頼文を入力]
           │
           ▼
  具体論点・仮説はあるか？
   ├── YES ──> 【Phase 2: 検証・構造化型レポート】
   └── NO  ──>  全体像や最新動向の把握が目的か？
                 ├── YES ──> 【Phase 1: 探索型レポート】
                 └── 曖昧 ─> 【Phase 1 で発信（末尾でPhase 2用の問いを提示）】
```

### 判定基準と具体例

| 評価項目 | Phase 1: 探索型レポート（Landscape & Issue） | Phase 2: 検証・構造化型レポート（Solution & Proof） |
|---|---|---|
| **依頼の特徴** | 広範なテーマ、全体像の把握、トレンド調査、未知分野のキャッチアップ | 特定の選択肢比較、要因分析、仮説検証、意思決定のための判断材料 |
| **問いの具体性** | 「何が問題か」「今どうなっているか」が未特定 | 「AとBどちらを選ぶべきか」「なぜ事故が起きたか」など具体的 |
| **発話パターン** | ・「〜の全体像を調べてほしい」<br>・「〜に関する最新動向や主要論点は？」<br>・「〜について基本から概観したい」 | ・「〜と〜のトレードオフを比較検証して」<br>・「〜のボトルネックとその解決策を示して」<br>・「〜を導入すべきか根拠をまとめて」 |
| **出力のゴール** | 読者に**地図**を示し、**次に解くべき3つの問い**を提示する | 読者に**結論**を示し、それを支える**論理と根拠**を展開する |

※ どちらか判断がつかない・境界にある場合は、まず **Phase 1（探索型）** としてレポートを作成し、L1概要および本文末尾で「次に深掘りすべき問い」を明示して読者と合意形成を行います。

---

## 2. レポート型の特徴と見出し設計の比較

| 項目 | Phase 1: 探索型レポート | Phase 2: 検証・構造化型レポート |
|---|---|---|
| **出発点** | 問いや論点が未定、景観が不透明 | 問い・論点・仮説が定義済み |
| **見出しの性質** | **構造・対立軸を示す分類見出し**<br>(例: `## 2. 処理方式の対立: Stream型 vs Batch型`) | **主張・結論を示す言い切り見出し**<br>(例: `## 2. リアルタイム処理にはStream型を採用する`) |
| **L1 概要の文脈** | 景観の要約 ＋ **今後解くべき3つの問い** | 答えの一文 ＋ **それを支える3つの主張** |
| **中心成果物** | ドメインマップ、対立軸整理、抽出された問い | 結論の一文、三層構造、論拠の展開 |

---

## 3. Phase 1: 探索型レポートの構造（景観・論点特定型）

問いがまだ定まっていない初期段階の調査であっても、単なる素材集めや百科事典にせず、**「全体像（マップ）」と「解くべき問い」を提示する完成されたレポート**として出力します。

### 構成要素

1. **`## 概要`（L1 概要と主要な問い）**
   * テーマの背景と現状の要約（2〜3文）。
   * 現状の主要な対立軸や構造的課題（1〜2文）。
   * **「今後、優先して検証・解明すべき3つの問い（Issues）」**（箇条書きで明記）。
   * 調査範囲・対象資料（1文）。

2. **`## 全体像`（ドメインマップ / トピック構造図）**
   * 主要要素、技術、プレイヤー、対立軸の関係性を表すMermaid図。

3. **`## 1. 背景・歴史 — <潮流の要約>`**
   * なぜこのテーマが現在注目・議論されているのかの文脈。

4. **`## 2. <概念・アプローチの対立軸>`（L2 本文: 分類・構造化）**
   * 単なる用語解説ではなく、「対立軸（A方式 vs B方式）」「トレードオフ」「ボトルネック」の切り口で構造化して記述。

5. **`## 3. 抽出された「重要な問い」の深掘り`**
   * **問い 1**: なぜ重要か、想定される仮説の選択肢。
   * **問い 2**: 調査を阻むボトルネック・未解決点。
   * **問い 3**: Phase 2で検証すべき具体的テーマ。

6. **`## まとめ — 次のPhase 2に向けた推奨アクション`**
   * どの問いから着手すべきかの優先順位の提言。

7. **`## 付録: 参考資料・用語集`（L3 付録）**
   * 一面的な定義集・主要論文・一次情報へのリンク（`[n]`表記）。

---

## 4. Phase 2: 検証・構造化型レポートの構造（解・根拠構築型）

問いや仮説が定まった後のレポートです。`report-structure-guide.md` の三層構造ガイドラインに厳格に準拠して作成します。

### 構成要素（`report-structure-guide.md` 準拠）

1. **`## 概要`（L1 答えと位置づけの提示）**
   * 答え（一文）＋ 軸 ＋ 位置づけ ＋ 3つの主張 ＋ 調査範囲（5〜8文）。

2. **`## 全体像`（論理構造図）**
   * 問い → 軸 → 分かったこと（主張） → 答え をつなぐMermaid図。

3. **`## 背景・歴史 — <経緯の主張>`**
   * 主張が成立するに至った文脈・歴史的経緯。

4. **`## <番号>. <対象名詞> — <主張の要約>`（L2 本文: 主張型見出し）**
   * 見出し自体が結論になっている章立て（例: `## 2. 消費層は必須 — Raw VaultをBIに直結しない`）。

5. **`## まとめ — 要点リスト`**
   * 読者が持ち帰るべき決定事項・主張の要約。

6. **`## 付録: 出典一覧`（L3 付録）**
   * `[n]` に対応する一次資料、データ、補足解析。

---

## 5. 実務でのレポート連携フロー

実務・プロジェクトでは、依頼者との対話を通じて Phase 1 から Phase 2 へとレポートを進化させます。

```
[調査依頼を受領]
    │
    ▼ （自動判定ルールを適用）
    │
    ├──【パターンA: 目的・問いが曖昧】
    │      │
    │      ▼
    │   【Phase 1 レポート発行】
    │   ・全体像のマップと「解くべき3つの問い（A, B, C）」を提示
    │      │
    │      ▼（読者・上司と合意形成: 「問いAを検証しよう」）
    │
    └──【パターンB: 問い・選択肢が明確】
           │
           ▼
        【Phase 2 レポート発行】
        ・「問いAに対する答えはXである。根拠は以下の3点」を提示
        ・意思決定・行動へつなげる
```
