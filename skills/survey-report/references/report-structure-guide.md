# Phase 2 レポートの「答えと根拠」構造ガイド

検証・構造化型レポート（Phase 2）で、読者が**答え**と**根拠**を一度で把握できるようにするための層設計。既定は L1（概要）・L2（本文）・L3（付録）の三層だが、**主張の数・図の有無・節の並びは重心（`gravity.md`）に合わせて決める。** ここで固定するのは「答えと根拠が対応していること」だけである。

## 三層の役割

| 層 | 見出し例 | 役割 |
| --- | --- | --- |
| **L1** | `## 概要` | 答えの一文、判断の軸、位置づけ、調査範囲。主張は必要数。 |
| **L2** | `## <番号>. <名詞> — <主張>` | 各主張を根拠・事例・反論処理で展開。見出しは結論の言い切り。 |
| **L3** | `## 付録: 出典一覧` | `[n]` 脚注に対応する一次資料・データ・補足、採用しなかった調査の枝。 |

L2 の各章は、L1 で示した主張と1対1で対応させる（順序・番号を揃える）。**主張の数は固定しない。** 答えを支えるのに必要な数だけ置き、水増ししない。

## L1 概要の必須要素（この順で含める）

1. **答え（一文）** — 依頼の問いに対する結論。
2. **軸** — 比較・判断に使った観点（例: コスト / 可用性 / 運用負荷）。
3. **位置づけ** — 推奨がどの選択肢・シナリオに当たるか。
4. **主張** — 答えを支える論点。L2 の章見出しの骨子になる（数は固定しない）。
5. **調査範囲** — 期間、地域、対象システム・資料の種類。

タイトル直後には、どの重心でも `## TL;DR` を3〜5項目（一項目一文）置く。`## 概要` はそれより詳しい位置づけを担う。

## `## 全体像`（論理構造図）

Mermaid などで **問い → 軸 → 分かったこと（主張） → 答え** の流れを示す。**図は必須ではない。** 関係が図で明確になる場合だけ置き、図にしかない事実を作らない。

## L2 本文（主張型見出し）

- 見出し形式: `## <番号>. <対象名詞> — <主張の要約>`
- 見出しだけ読んで結論が追えること（叙述見出しは避ける）。
- 各章の中身: 主張の根拠 → 具体例・データ → 限界・反論への一言。
- 本文中の根拠は `[n]` で L3 に接続する。
- 前重心なら要点から根拠へ、中重心なら比較軸から対象へ、後重心なら問いから証拠・考察へ進める。

## その他の必須セクション

- **`## 背景・歴史 — <経緯の主張>`** — 答えが妥当な文脈（なぜ今この判断か）。後重心では成立過程が本文の中核になりうる。
- **`## まとめ — 要点リスト`** — 決定事項・持ち帰り主張の箇条書き（L1 の答えと矛盾しない）。冒頭の言い換えにしない。

## L3 付録

- 見出し: `## 付録: 出典一覧`
- `[n]` ごとに: 出典名、URLまたは文献情報、該当データの要約（1行でも可）。
- 調べたが採用しなかった重要な枝と理由、本文から外した素材も残す。

## 品質チェック（出力前）

- [ ] L1 に答え・軸・調査範囲がある
- [ ] L2 見出しは言い切りで、L1 の主張と対応している（数は固定しない）
- [ ] 全体像の図を置いた場合、問いから答えまでつながっている
- [ ] 本文の `[n]` が付録にすべて存在する
- [ ] `checklists.md` の共通テスト・Phase 2 テスト・選んだ重心のテストを通過した
